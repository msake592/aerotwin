# Robotics integration feasibility on Apple Silicon

Documentation review, 2026-11-05. The recommendations are candidates for later validation. This review exercised the standalone core and Python tooling. Robotics packages, graphics, networking, and simulator assets were outside the local audit.

| Technology | Role and adoption | Apple Silicon and native setup | Linux alternative, graphics, and risk |
| --- | --- | --- | --- |
| ROS 2 | Message transport and adapters in M3 | Use the distribution's platform matrix as the support boundary. Jazzy targets Ubuntu 24.04 on amd64 and arm64 at Tier 1. Treat native macOS source or community packaging as an exploratory path and verify packages individually. | Prefer Ubuntu 24.04 as the initial integration candidate. An ARM Linux VM or remote host can run transport without a GPU. Verify DDS discovery across host and guest and verify package availability. [ROS platform tiers](https://www.ros.org/reps/rep-2000.html#jazzy-jalisco-may-2024-may-2029) |
| Gazebo Harmonic | 3D physics, simulated observations, and ground truth in M3 | Official Homebrew bottles cover Apple Silicon on macOS Sequoia. Other macOS versions may need source builds. Upstream reports macOS GUI instability. | Start with the Linux server and a minimal scene. Verify graphics separately for camera and other rendered sensors, including in headless operation. VM GPU support and rendering performance need testing. [macOS installation](https://gazebosim.org/docs/harmonic/install_osx/), [platforms and GUI caveats](https://gazebosim.org/docs/harmonic/) |
| PX4 SITL | Simulated flight control in M3 | PX4 documents a supported Apple Silicon development setup using Xcode tools, Homebrew, and optional Harmonic tooling. Verify the selected PX4 revision and its Gazebo pairing together. | An Ubuntu host is the baseline candidate for the coupled stack. SITL compute does not itself require CUDA. Rendered sensors inherit Gazebo graphics requirements. Validate simulator transport, clock behavior, and NED/FRD conversions. [PX4 macOS guide](https://docs.px4.io/main/en/dev_setup/dev_env_mac), [PX4 Ubuntu guide](https://docs.px4.io/main/en/dev_setup/dev_env_linux_ubuntu) |
| RViz2 | M3 integration diagnostics and M6 explainable views | Treat native source builds as exploratory. Verify Qt, OGRE/OpenGL, and plugin compatibility before relying on native macOS. | Prefer a Linux desktop with working OpenGL or remote desktop with suitable graphics. A transport-only container is insufficient for interactive visualization. Verify TF alignment, timestamps, and plugin availability. [RViz upstream](https://github.com/ros2/rviz) |
| Unity | Optional visualization client at M6 if existing tools leave a clear gap | Unity documents an Apple Silicon editor using Metal. Check editor version and plugin architecture compatibility. | A supported Linux editor is another option. Check the vendor graphics requirements for that host. Keep coordinate conversion, replay timing, and schema compatibility in the visualization client. [Unity system requirements](https://docs.unity3d.com/6000.0/Documentation/Manual/system-requirements.html) |
| NVIDIA Isaac Sim / Isaac Lab | Optional later synthetic-data or robotics research, after M6 and only with a scoped need | NVIDIA documents Linux and Windows for Isaac Sim. macOS can serve as a streaming client for a supported remote host. | Use a supported remote RTX workstation or Linux GPU container. Verify GPU, VRAM, driver, and Lab/Sim release pairing. Apple Silicon virtualization does not provide the required RTX device. [Isaac Sim requirements](https://docs.isaacsim.omniverse.nvidia.com/6.2.0/installation/requirements.html), [remote streaming](https://docs.isaacsim.omniverse.nvidia.com/latest/installation/install_faq.html) |

M3 should first prove a minimal Linux end-to-end scenario with a compatible version set, separate truth and observation paths, and explicit frame and clock conversions. Native macOS or ARM VM experiments can then be compared against that baseline. Container packaging and graphics acceleration remain adoption decisions for the relevant milestone.

The [M3.1 readiness report](../reports/m3-integration-readiness.md) records the later platform audit, executed checks, and runtime gates.
